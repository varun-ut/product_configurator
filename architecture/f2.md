Complete flow, from the moment you type the URL and hit Enter:

---

## Phase 1 — Getting the App Shell

**1.** You type `app.univicoustic.com` in the browser.

**2.** DNS resolves that domain → points to CloudFront.

**3.** Your browser asks the nearest CloudFront edge: *"give me index.html"*

**4.** CloudFront serves `index.html` from S3 (the React build). ~5ms. FastAPI not involved.

**5.** Browser reads `index.html`, sees it needs `main.js`, `main.css` → asks CloudFront for those too. Served from S3. FastAPI not involved.

**6.** React app boots up in your browser.

---

## Phase 2 — Loading the Catalog

**7.** React's `useEffect` fires on mount → calls `GET api.univicoustic.com/api/products`

**8.** That request hits CloudFront → CloudFront is configured to forward `/api/*` requests to the ALB (load balancer). It does **not** cache this (it's dynamic data with Auth headers potentially).

**9.** ALB receives the request → routes it to one of the running ECS Fargate tasks (your FastAPI container).

**10.** FastAPI runs the query:
```sql
SELECT products, categories, designs, cdn_urls FROM ... JOIN ...
```
against Postgres RDS.

**11.** Postgres returns rows → FastAPI builds the JSON response with full CDN URLs:
```json
{ "thumbnail_url": "https://cdn.univicoustic.com/products/.../VMD-LT-001-thumb.webp" }
```

**12.** JSON travels back → ALB → CloudFront → your browser. Total: ~80-120ms.

**13.** React state is populated. Sidebar renders — product types, categories, all dropdowns appear. But thumbnails aren't loaded yet, just their URLs are known.

---

## Phase 3 — Loading Thumbnails

**14.** React renders the design grid. For each thumbnail `<img src="https://cdn.univicoustic.com/...thumb.webp">` the browser fires an image request.

**15.** Each request goes to CloudFront (nearest edge). These are static files — CloudFront caches them aggressively.

**16.** Cache hit → image returns in ~10-20ms. Cache miss (first ever request to that edge) → CloudFront fetches from S3 → caches → returns. ~80ms.

**17.** Thumbnails appear in the grid. FastAPI not involved at all in steps 14-17.

---

## Phase 4 — You Select a Design

**18.** You click "Line & Texture Design 1".

**19.** React already has the `preview_url` from the JSON it loaded in Phase 2. It updates state → canvas component receives new texture URL.

**20.** Browser requests `VMD-LT-001-preview.webp` from CloudFront. Served from edge cache.

**21.** Canvas renders the panel texture onto the room scene — pure browser-side JavaScript, zero network calls.

**No API call was made in Phase 4.**

---

## Phase 5 — You Change Another Setting (size, density, emboss)

**22.** React updates local state. Canvas re-renders with the new config.

**Again, no API call.** All data was loaded once in Phase 2.

---

## The Full Picture

```
Phase 1 (app shell)
  Browser ──▶ CloudFront ──▶ S3
                              (index.html, main.js, main.css)

Phase 2 (catalog data)
  Browser ──▶ CloudFront ──▶ ALB ──▶ ECS(FastAPI) ──▶ RDS Postgres
                                                           ↓
                              JSON with CDN URLs ◀─────────┘

Phase 3 (images)
  Browser ──▶ CloudFront ──▶ S3
                              (thumb.webp files)

Phase 4+ (interactions)
  Pure browser state — nothing leaves the device
```

---

**FastAPI was called exactly once** — Phase 2, step 7. Everything else was either S3/CloudFront or local browser computation. That's why this architecture handles 30 concurrent users with almost no backend stress — the backend is only doing one lightweight DB query per user session.
